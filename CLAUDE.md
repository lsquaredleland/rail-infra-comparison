# Infrastructure Comparison

Interactive map that overlays up to four cities or regions at true scale, with city limits, rail networks
(from OpenStreetMap), stations and main roads. Static site: one `index.html` (canvas, no framework, no build
step) plus one JSON file per region in `site/data/`. A Rust extractor (`extract/`) and a Python build (`pipeline/`) produce those files from the OSM planet.

Run the site: `cd site && python3 -m http.server 8765`, then open http://localhost:8765/index.html.
It was previously published as a Claude artifact; it works on any static host.

## Layout

    site/index.html          the whole app (UI, rendering, selection and rotation, stats table); site/config.js tunable map numbers
    site/data/<id>.json      one file per region (roads in <id>.roads.json, loaded with the Streets layer), index.json, stations_<id>.json
    extract/                 ra-extract (Rust): planet -> run2/rail_<g>.jsonl, geo_<g>.jsonl, bnd_rels.json for every group
    pipeline/groups.json     region groups: map box, core box for secondary/tertiary roads, boundary relation ids
    pipeline/refresh.sh      the whole pipeline in one command (extract, build, station model)
    pipeline/build.py        builds site/data/*.json from run2/ (REGIONS: the 21 regions)
    pipeline/new_regions.py  adapter: reads run2 jsonl into build.py's structures
    pipeline/run_all.py      builds regions in parallel, one process per group
    pipeline/stations.py     station model (complex / station / stop point) of any built region
    pipeline/qa/<id>.json    output of the CHECK lines of the last build (not in git)
    tests/smoke.py           Chrome smoke test (requirements-dev.txt)
    docs/rust-pipeline.md    the pipeline in depth: design, code, optimizations, pitfalls, porting checklist
    run2/                    extracted data (not in git; regenerated by refresh.sh)

## Build (repeatable: monthly refresh or a new city)

    pip install -r requirements.txt             # shapely, pyproj, numpy
    brew install rust                           # the extractor
    pipeline/refresh.sh                         # everything, about 3 minutes (PYTHON=..., RA_PLANET=..., RA_STATIONS="hk sz")
    pipeline/refresh.sh prd hk,sz               # one-off: extract one group, build some regions

refresh.sh runs: `cargo build --release` -> `ra-extract` (all groups in one read of the planet) -> `run_all.py` (one process per group, all its
regions, in parallel under a memory budget) -> `stations.py` for the regions in RA_STATIONS. Monthly: download the new planet, set RA_PLANET,
run refresh.sh, look at the site, run tests/smoke.py. New city: add a group to `pipeline/groups.json` (box S,W,N,E; core box for secondary
and tertiary roads or null; boundary relation ids) and a region to REGIONS in build.py (relation ids, anchor, streets, big), then
`pipeline/refresh.sh <group> <region>`; add it to RA_STATIONS / STATION_DATA in index.html for a station model.

Lower-level commands:

    extract/target/release/ra-extract --planet PLANET --config pipeline/groups.json --out run2 [--groups a,b] [--threads N]
    cd pipeline && python3 run_all.py [id,id]   # build; ONLY=id python3 build.py builds in one process; RA_NEW / RA_OUT override folders
    cd pipeline && python3 stations.py <id>     # station model of any built region -> site/data/stations_<id>.json

- build.py loads only the groups of the regions it builds and merges its regions into `site/data/index.json` (under a lock).
- Region definitions: `REGIONS` in build.py (relation ids, anchor point, `streets` max road class, `big`, `subs`, `clip`); groups, boxes and
  boundary ids: `pipeline/groups.json` (read by ra-extract, new_regions.py and run_all.py's grouping via build.py).

## Pipeline performance (planet-260928, 14-core Mac, 36 GB; measured 2026-10-12)

| step | before | now |
|---|---|---|
| extraction, all 12 groups | about 1 h of osmium cuts (2 min each one at a time) + Python | ra-extract 79 s, 4.7 GB peak |
| extraction, Greater Bay Area only | 484 s | 65 s |
| build, all 21 regions | about 9 min | 76 s |
| build, Greater Bay Area | 331-362 s | 26 s |
| station model, Greater Bay Area | 142 s | 21 s |
| everything (refresh.sh) | | 167 s |

What made the difference: ra-extract reads the planet once for all groups, decodes only the blob type each pass needs (index of blob headers;
the planet is sorted), skips node blobs without a needed node, and decodes in parallel with libdeflate from positioned reads (a memory map
was I/O bound: 174 s for one group). In build.py, 264 of 339 s were shapely intersection/intersects against unprepared region polygons:
the polygons are now prepared (shapely.prepare, and the prepared one must be the caller), clip() skips the intersection for pieces wholly
inside or outside, each rail segment is clipped once, tree queries use a square instead of a circle buffer, corridor_km samples with one
vectorised call per piece, and station names are normalised through a cache. In stations.py, 40 million track-station tests became R-tree
queries and the 600 m boundary buffer is computed once. Outputs are unchanged (byte-identical for the build and station model of the Greater
Bay Area; one station's line list is now deterministic).

Old system vs new, all regions: land, stations and network km the same (km within 0.3); a few more lines where ra-extract finds train routes
the old rail slice missed (Zurich 54 -> 66); Tokyo 23 wards now marks only Tokyo, Ueno and Shinagawa as high-speed stations (the old extract
marked 16 more, wrongly); ways are no longer cut at the box edge.

## Data format (per region JSON)

Coordinates are metres in an azimuthal-equidistant projection centred on the region's anchor, stored as integers
in units of `unit` (5 m, or 10 m for `big` regions; the site reads `unit` from each file), delta-coded (`enc_line`: list of dx,dy pairs). Curvature is handled per region by that projection.

- `land`, `legal`: polygons (rings of delta-coded points). `legal` is the official boundary, `land` is clipped to coastline.
- `divs`, `div_names`: internal division lines and labels (wards, counties).
- `lines`: `[mode, name, colour, km, maxspeed, built, builtSrc]` (maxspeed: fastest tagged way of the line in km/h, 0 if unknown; built: `start_date` or `opening_date` of the route relation as written in OSM, else the earliest start_date of its track with builtSrc `track`, planned opening for lines under construction with builtSrc `planned`; '' if none). `rail`: `[lineIndexes, insideFlag, enc]`.
- Rail modes: 0 metro, 1 regional, 2 light rail, 3 tram, 4 monorail, 5 funicular, 6 high-speed, 7 other main-line, 8 rail under construction, 9 freight, 10 high-speed under construction. Network totals exclude 8, 9, 10.
- `stations`: `[x, y, name, localName, kind, inside, lineIndexes, tier, nPhysicalLines, built]` (built: station `start_date` or `opening_date` as written in OSM, earliest of the merged objects, '' if none).
  tier 0 normal, 2 high-speed stop, 3 main high-speed station, 4 main (non-high-speed) station.
  UI rank: 0 single-line stop, 1 interchange (2+ lines), 2 major interchange (`nl >= major_min`, default 4, 6 for New York), 3 HSR stop, 4 main HSR station, 5 main station.
- `roads`: in `<id>.roads.json` as `{unit, roads}` (the main file has empty arrays and `roads_file`), four arrays by class (0 motorway/trunk, 1 primary, 2 secondary, 3 tertiary); which are included depends on `streets` in REGIONS. Only motorway, trunk and primary are extracted over a whole box, secondary and tertiary only inside the city core boxes (`core` in pipeline/groups.json); ramps (`*_link`) are dropped. build.py joins the pieces OSM cuts at every junction (`linemerge`, polylines drop 5-35x) and drops pieces shorter than 400 m on big regions (60-120 m on city regions).
- `stats`, `extent`, `centroid`, `anchor`, `major_min`.

## Station model (pilot: Hong Kong, Shenzhen)

Follows `../rail-atlas spec/docs/04-station-model.md`. `python3 stations.py hk` or `sz` (needs shapely, pyproj; reads `site/data/<id>.json` for the boundary, so build the region first) writes `site/data/stations_<id>.json`:
`stations` (summary: id, status built/construction/proposed, name, local, modes, x, y in metres in the region projection, platforms, tier, tier_name, score, terminus, complex, grouping), `complexes`, `lines` (route metadata by line key: ref, names, network, operator, from/to, wikidata, dates, service, electrified, voltage, gauge, max speed, relation ids, station count and order), `detail[id]` (lines with keys, names in all languages, `meta` tags such as operator, network, wikidata, ref, uic_ref, start/opening date, wheelchair, level, opening date, platform geometry, footprint, nearby tracks, stop positions, entrances, source OSM ids).
- Stations under construction or proposed: from `railway=proposed`/`proposed=station` nodes, `construction:railway=stop|station` nodes and `building=construction` + `construction=train_station` areas, clustered by name within 500 m or by lying within 80 m of such an area (mode-compatible). A cluster is dropped if an already open station of the same name and compatible mode is within 500 m (a high-speed hub next to a metro station of the same name stays separate). Example: Xili High-Speed Railway Station in Shenzhen is a `building=construction` area plus several `construction:railway=stop` nodes; its alternative names are kept as `names.aka`.
- Steps: stations from `stop_area` relations, then station nodes/areas without one (platforms and stop positions attached within 300 m mainline / 100 m other, name must agree); merge same-mode duplicates (shared wikidata/uic_ref/railway:ref, or same normalised name within 400 m; bracketed qualifiers like "(Line 2)" and trailing 站/駅/역 are ignored); lines from route relations (distinct route_masters); complexes from `stop_area_group`, else different modes sharing wikidata or name within 300 m; points; size score.
- Size score = 3 x mainline platforms + 2 x mainline tracks through the footprint (max 12) + footprint area m2 / 1500 + 8 if a mainline track ends in it. Metro and tram platforms do not count, line counts never rank. Tiers: Major >= 80, Large >= 35, Medium >= 10, Small >= 4, else Stop. Cut-offs are tuned by eye on Hong Kong only; the spec asks for a hand-made answer list.
- Platform count = distinct platform refs (split on ; , /) plus unreferenced platform objects; `null` when no platforms are mapped (about 30% of Hong Kong stations), shown as "platforms not mapped".
- Station footprint = station/building areas of the stop area, else a `landuse=railway` area under 40,000 m2 containing the point.
- Input: `run2/rail_<group>.jsonl` from ra-extract (ways carry node ids); no separate station extract is needed.
- Site: `attachStationData` in index.html loads `STATION_DATA[id]`, matches each drawn station to the nearest built model station within 150 m (kind-compatible preferred) and adds under-construction and proposed stations as hollow dashed markers (hidden with the "Rail under construction" toggle). Station outlines (footprints) are drawn on the map from scale 0.04 px/m up: solid for open stations, dashed for planned ones. Hover tooltip adds "Size: X, N platforms"; double-click a matched station opens the station view panel (plan of footprint, platforms with refs, tracks, stop positions, entrances; lines; stations of the same complex; OSM ids). Esc closes it.
- Station dedupe in build.py (drawn stations): the old rule also merged names where one was a prefix of the other within 600 m, which swallowed real stations (Shinjuku-sanchome into Shinjuku, Akasaka into Akasaka-mitsuke). Now only exact, local-name or normalised-equal names merge (all regions).
- Planned stations have the same taxonomy as open ones: size tier and score, complex, modes, platform count (or the declared `platforms` tag, flagged `platforms_src: tag`), and UI rank 0-5. Their lines come from `railway=construction` ways (grouped by name, key `x|<construction type>|<name>`) that touch the station's stop positions or outline (70 m / 40 m); `hsr` is set when such a way is `highspeed=yes` or has maxspeed or maxspeed:designed >= 200. Their opening date is the station's own `opening_date`/`start_date`, else the planned opening of its lines (`opening_src: line`). They are drawn with the normal rank shapes but dashed.
- Extra metadata kept: stations `platforms`, `fare_zone`, `website`, `owner`, `ownership`, `operator:short`, `wikimedia_commons`, `building:levels`, `location`, `note`, `description`, `opening_date`, `start_date`; lines `operator(:en/:zh/:type)`, `from/to` (+ :en, :zh), `fee`, `description`, `owner`, `ownership`, `network:wikidata`, `website`, `passenger_lines`, plus aggregates from member ways: `track_km` (all tracks counted), `tunnel_km`, `bridge_km`, `gauge`, `electrified`, `voltage`, `frequency`, `track_start_date`, `maxspeed` and `maxspeed_designed`; construction lines `opening_dates`, `hsr`, `usage`. OSM has no construction start date tags in these extracts; `opening_date` is the planned opening.
- UI: tooltips and the station view show one fact per line (`lineFacts` / `factRows` in index.html). Drawn lines are joined to route metadata by name (`baseName`), so line tooltips show operator, route, opening, power and so on where a match exists (39 of 73 Shenzhen lines).
- Known gaps: MTR East Rail and Tuen Ma are `route=train` in OSM, so those stations count as mainline and split from their metro sibling (same complex). West Kowloon HSR has no mapped services (0 lines). Only Hong Kong and Shenzhen have this data; other regions show the simpler tooltip.

## Rail from the planet for every region, and the CHECK lines

History: the original Overpass pull was incomplete and dated per tile (Shenzhen Line 13 stopped 13.5 km short of Lisonglang: 10 Line 13 ways
listed in the pull's own route relations were never returned). Everything now comes from the planet through ra-extract, and the checks below
would catch a gap like that.

build.py prints `CHECK <id>` lines (also collected by run_all.py; details in `pipeline/qa/<id>.json`):
1. stops with no drawn track of any line within 300 m (a stop of a route far from all drawn track means track is missing; Line 13 would have been flagged at 13.5 km). Looking at all lines avoids false alarms from route variants that share track under another name.
2. route member ways that are in the extract but were dropped by the adapter (not rail, fewer than two nodes). Members that are not in the extract at all lie outside the bbox and are ignored.
Test hook: `RA_TEST_DROP_WAYS=id,id ONLY=<region> python3 build.py` removes ways from the track data to show the check firing. Some routes (long-distance train services in London) list stops but no track; the check does not flag them because other lines' track is near.

## Data sources

- Everything comes from the OSM planet (planet-260928, ODbL) through ra-extract: rail, stops, stations, roads, coastline and boundaries for every group in `pipeline/groups.json`. The Overpass pulls and the osmium-based Python extractors were removed after their output matched (2026-10-12).
- Boundary relation ids per group are in `pipeline/groups.json` (and per region in `REGIONS`).
- OSM data is ODbL. Keep the attribution.

## Decisions and rules worth keeping

- Rail line grouping: ways are grouped by route relation (ref/network/name); unrouted ways are grouped as "Other ... track". Yards, sidings, crossovers, industrial and military track are dropped. Freight and under-construction types have their own toggles.
- Cropping: only lines that serve the city are kept. A line (route group) needs at least 200 m of track inside the limits; lines that never enter, e.g. Shenzhen Metro in the Hong Kong context buffer, are dropped with their stations (outside stations survive only if a kept line calls there). Lines that do enter keep their track beyond the limits, up to the context buffer. Pooled "Other ... track" buckets are judged per segment (only track touching the city stays), since they mix unrouted track from everywhere. Roads are not cropped this way. Effect: Hong Kong went from 81 to 46 lines and 273 to 176 stations; inside totals are unchanged.
- Station lines: each route stop is owned by one station within reach (radius by mode: metro 200 m, light rail 160 m, tram 110 m, rail 330 m,
  high-speed 700 m at high-speed stations), preferring the station named like the stop, else the nearest that can serve that kind of line. Other
  stations within reach get the line only if they serve that kind of line themselves, have no stop data, or are the same place (one name
  contains the other, or within 40 m). Lines without stop data count by proximity, for light rail, tram, monorail and funicular only within
  60 m of the track. 'Other ... track' buckets are a station's line only when nothing else serves it. So a station hides with its lines: in San
  Francisco the cable car stops no longer claim the Muni T, the F-line stops on Market Street no longer claim the Muni Metro subway beneath
  them, and Civic Center keeps BART and Muni Metro. Known misses: Zurich's Polybahn top station and the ETH tram stop, and New York's Howard
  Beach and the AirTrain, are no longer counted as interchanges.
- Station merge pass (`merge_close_stations` in build.py, after each station's lines are known; log in `pipeline/qa/<id>_merged_stations.json`, count printed as `MERGE`): the first dedupe merges identical names within 600 m; the second merges close stops that are the same stop mapped more than once. Rules: A same cross streets in any order or same name apart from street type and a trailing direction word (<= 150 m); B a stop named after one street of another's "X & Y" name and sharing a line (<= 80 m); C light-rail, tram or cable-car stops with exactly the same lines, direction words ignored (opposite platforms, <= 50 m); D stops sharing a line that are on the same spot (<= 12 m) or within 35 m when one is named "X & Y". Lines are compared without inbound/outbound words. Deliberately not merged: consecutive stops on one line and differently named stations of one complex (Ueno-okachimachi, Ueno-hirokoji). San Francisco 243 -> 222; the rest are real stops (median distance to the nearest other stop 146 m), so clutter there is handled by the tram-stop zoom rule below. Other regions change by 0-5 stations.
- Stations mapped as areas: many stations exist in OSM only as a closed way (or multipolygon) tagged railway=station, with no tagged node; most MTR stations in Hong Kong (Central, Admiralty, Causeway Bay ...), 442 in Shanghai, 400 in the Greater Bay Area. `new_regions.py` takes the centre of such an outline as the station position (`stw`). Before this fix those stations were silently missing: Hong Kong had 41 metro stations instead of 98, Shanghai 256 instead of 494. When a node also exists the normal same-name dedupe merges the two.
- Corridor length: `corridor_km` samples every 20 m and counts a sample only if no already-counted track is within 35 m, so parallel tracks count once.
- High-speed: a way counts as high speed if `highspeed=yes` or maxspeed >= 200. A route counts as a high-speed service only if the relation says so, or it is inferred from track AND the route is not commuter-like (average stop spacing under 6 km). This stops commuter lines on high-speed-tagged track (Seoul Gyeongui-Jungang, Jungang, AREX) from marking all their stops as high-speed.
- Main stations: `MAIN_BY_GROUP` in build.py lists canonical terminals per region (matched on normalised names). `MAIN_RE` handles Chinese main HSR stations.
- Station dedupe merges identical, same-local-name or normalised-equal names within 600 m (prefix matches are not merged: Shinjuku and Shinjuku-sanchome stay apart).
- Interchange size: `MAJOR_MIN` per region (New York 6 because subway services overlap on shared track).
- Boundary polygons: ra-extract fetches boundary relations whole, so rings close; `rel_poly` still closes any open chain with a chord as a safeguard. Regions are clipped to their group box (`clip=BB[...]`) so sea beyond the box is not counted as land.
- Big regions simplify more (`big=True`): land buffer is simplified, small polygons dropped, 10 m grid, rail simplified at 15 m (6 m otherwise), roads at 50 m (12 m otherwise), and the lowest street class is dropped when `streets` >= 2 (Bay Area, Tokyo Metropolis, Beijing Municipality, Chengdu Prefecture, Shanghai).
- Colours, widths, opacity: non-HSR rail opacity 0.6, HSR opaque; widths in the `MODES` array in index.html.

## UI behaviour (index.html)

- Up to four cities; each has an anchor ("Downtown") or centre alignment. Layers: Outline, + Transit, + Streets.
- Selecting a city (click) shows a rotation ring with a knob; click anywhere again to deselect. Drag a selected city to move it, drag the knob to rotate (snaps to 15 degrees, plus or minus 3 to 5). Keys: Q/E rotate 15 degrees, Shift for 1 degree, R reset, Esc deselect, Tab cycles. Space, middle mouse or two-finger drag pans while selected. A rotation sheet gives a slider, nudge buttons, "North up" and "Match axis".
- The compass button (and R with nothing selected) resets map rotation and every city's rotation to north.
- Hovering a line shows its name, type, km in the city and max speed when tagged (mph or km/h following the unit toggle). Hovering a Hong Kong or Shenzhen station also shows size tier and platform count.
- Tram stops: stations of kind light rail or tram whose lines are all light rail, tram or cable car, and that are rank 0-1, are not drawn at all (no dot, label or tooltip) below `stations.tramStopMinScale` = 0.07 px per metre (see config.js).
- `site/config.js` holds the tunable map numbers: zoom limits, and per station rank the scale at which its dot appears (`dotMinScale`) and its name appears (`labelMinScale`), dot sizes, label fonts, the tram-stop threshold, the outline threshold and the tooltip hit radius. Scale is pixels per metre (a table of ground widths is at the top of the file). Current rank rules: 5 main station dot always, name from 0.0016; 4 main high-speed station dot always, name from 0.0012; 3 high-speed stop dot from 0.02, name from 0.04 (was 0.005 / 0.012: stops along a high-speed line showed before ordinary stops); 2 major interchange 0.002 / 0.009; 1 interchange 0.004 / 0.02; 0 single-line stop 0.008 / 0.04.
- Line colors: the map button under Fit (and the "Line colors" checkbox) toggles each line's OSM colour; off means every line takes the colour of its rail type (`lineColor()`), with the city-coloured casing kept. The old off mode that painted all lines in the city colour is gone.
- Drawing performance (pan and zoom): the browser strokes and dashes a whole path, off-screen parts included, so at close zoom a dashed outline of a big region became millions of dashes (Greater Bay Area: 9 fps while dragging at every zoom; on the CPU 1.9 s per frame at scale 1.5, of which the dashed city outline 1.6 s and division lines 1.1 s). Now every stroked line (rail, roads, outlines, division lines, land edge) is kept as pieces of at most 96 vertices and about 1.5 km, each with a bounding box (`chunkInto`; long edges are split), and the whole path is the join of the same pieces, so dashes restart at the same places whichever is drawn. Each frame strokes only the pieces that touch the screen (`localView`, `pickPieces`, `cullPath`, `railPath`), or the whole path when more than half of it is visible; the hover hit test looks only at pieces near the pointer. Two canvases: `#map` (land, roads, outlines, rail, station outlines) is redrawn only when the view or the map changed; `#over` (hovered line, station dots, labels, anchors, rotation ring) is redrawn every frame, so hover never redraws the map (`draw()` redraws both, `draw(true)` only the overlay unless the view moved).
  Result (visible Chrome window, M4 Max, 1728x1050 at 2x, two regions with Streets, dragging): Greater Bay Area + Shenzhen at scale 1.5 went from 10 to 120 fps, at 0.6 from 47 to 120; Jiangnan + Shanghai at 1.5 from 27 to 120; Tokyo + Seoul+ and New York+ + London at 1.5 from 74 to 120; every other view tested stays at 120.
  Measure in a visible Chrome window (Playwright `headless=False`): headless Chrome throttles requestAnimationFrame (9 fps doing nothing), and timing with `getImageData` forces the canvas onto the CPU, which is not what users get. Tried and dropped: shifting the map image during a pan and drawing only the new strips (on the GPU it was slower than a full culled redraw, 10-18 fps against 120 at wide zoom), and clipping the land fill to the screen (no gain).
- Stats table: land area, lines, stations, interchanges, network km by type, under construction, freight.

## Known issues and to-do

- File size: the main region files total about 5.8 MB raw (1.8 MB gzip) and roads 2.8 MB raw (1.1 MB gzip), fetched only with the Streets layer; it was 19 MB raw / 6 MB gzip with roads inside every file. Ideas left: delta + varint binary instead of JSON text, dual-carriageway merging, per-zoom road tiles.
- Paris is Paris plus Hauts-de-Seine, Seine-Saint-Denis, Val-de-Marne (about 763 km2), not the Metropole du Grand Paris (no boundary relation found).
- Shanghai (about 7,400 km2) and Jiangnan (about 32,700 km2) overstate land: estuary and offshore water inside the extraction box is counted as land.
- Seoul+ is about 12,000 km2 (earlier estimate 11,800).
- London and Paris still use the default major interchange size of 4; they may be as cluttered as New York was.
- Paris main-station names are the least verified; add missing ones to `MAIN_BY_GROUP['par']`.
- The station model (complexes, platforms, size tiers, planned stations, lines metadata) exists only for Hong Kong and Shenzhen (`stations.py`); other regions show the older tooltip.
- "Match axis" is disabled for near-round cities (elongation under 1.15).
- A few long straight rail lines in the surrounding regions (Paris+, New York+) are real (sparsely mapped), not bugs.

## Conventions

- The user prefers no em dashes in written replies and docs.
- Never modify the planet file. `run2/` and `site/data/` are generated: change the code or `groups.json` and run `pipeline/refresh.sh`, do not edit them by hand.
- Prefer small, verifiable steps; rebuild one region and look at it in a browser before rebuilding all.
